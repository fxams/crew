# x402 pay-per-call (no API key)

CrewPay lets AI agents launch coins on Pump.fun, Bags, and Zora and auto-hire a crew of real KOLs. Those KOLs are paid onchain from creator fees (60% crew / 15% launching agent / 25% treasury). CrewPay is non-custodial and never holds the launcher key. Later, agents will be able to hire humans for any task that needs a person, with jobs paid automatically on delivery, more chains, and KOL reputation. This is not an earnings promise and not a partnership claim.

CrewPay accepts [x402](https://docs.x402.org) **v2** (HTTP **402 Payment Required**) on agent launch + Autohire. Agents pay a small **USDC** fee per request instead of claiming a `crew_ak_…` key.

Existing `x-crew-api-key` auth is unchanged. x402 is an alternative path, **off unless `X402_ENABLED` is set**.

Fee map on launches is still **60% hired KOL crew / 15% launching agent / rest treasury** (5% referrer when a referred key is bound to the payer wallet). The launching agent does not receive the 60% crew slice. Keys, fee split, and on-chain config are not changed by x402.

## Enablement (server)

| Variable | Purpose |
| --- | --- |
| `X402_ENABLED` | `1` / `true` to turn the feature on |
| `X402_FACILITATOR_URL` | Facilitator base URL (default `https://x402.org/facilitator`). For Solana USDC, use a facilitator that supports Solana (e.g. [Coinbase CDP](https://docs.cdp.coinbase.com/x402/network-support)). |
| `X402_PAY_TO_EVM` | USDC recipient on Base (default `ZORA_TREASURY_ADDRESS`, then `CREW_BUYBACK_WALLET_EVM`). Env-driven — no address is hardcoded. |
| `X402_SOLANA_PAY_TO` | USDC recipient on Solana mainnet (preferred). Omit to advertise Base only. |
| `X402_PAY_TO_SOL` | Legacy alias for `X402_SOLANA_PAY_TO` |
| `X402_PRICE_LAUNCH_USD` | Launch / unsigned / submit / dry-run (default `0.10`) |
| `X402_PRICE_AUTOHIRE_USD` | Autohire (default `0.02`) |

Do not commit private keys. Pay-to addresses are public receiving wallets. If no Base address is configured, the 402 challenge omits the `eip155:8453` accept.

## Flow

1. `POST /api/agent/launch/unsigned` (or `/submit`, `/dry-run`, `/launch`, `/autohire`) **without** `x-crew-api-key`.
2. Server responds **402** with `x402Version: 2`, header **`PAYMENT-REQUIRED`** (base64), and JSON `accepts[]` (exact USDC on `eip155:8453` and, when `X402_SOLANA_PAY_TO` is set, `solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp`) plus `extensions.bazaar`.
3. Client signs a payment and retries with header **`PAYMENT-SIGNATURE`** (legacy **`X-PAYMENT`** still accepted).
4. Server verifies + settles via the facilitator, then fulfills the request and returns **`PAYMENT-RESPONSE`**.

`GET /api/kols` stays public and free.

Unauthenticated probes reach the 402 before body schema checks, so x402scan can register the routes without a JSON body.

## Identity

The **payer wallet** is the agent identity:

- Rate-limit fingerprint
- **15% launching-agent** fee-share when the payer chain matches the launch (Solana payer → Pump/Bags desk; EVM payer → Zora desk). Otherwise the `launcherPubkey` / signer still receives that slice.
- Referral: if that wallet already owns a claimed key with a KOL `referralCode`, the 5% referrer cut applies.

## MCP (`crewpay-mcp@1.2.14`)

Hosted `mcp.crewpay.dev` is **not** an x402 resource server. It does not wrap tools with x402 payment and never holds a shared x402 wallet — pass `x-crew-api-key` there. Bazaar MCP discovery metadata is therefore **not** advertised: cataloging paid MCP tools would require the hosted MCP to receive USDC, which would change custody.

Local stdio can **pay the REST API** (client of the HTTP routes, not a paid MCP resource):

```json
{
  "mcpServers": {
    "crewpay": {
      "command": "npx",
      "args": ["-y", "crewpay-mcp@1.2.14"],
      "env": {
        "X402_EVM_PRIVATE_KEY": "0x…",
        "CREW_LAUNCHER_KEY": "your-solana-secret-base58",
        "CREW_API_URL": "https://api.crewpay.dev"
      }
    }
  }
}
```

If `CREW_AGENT_API_KEY` is set, MCP uses the key and does not pay. MCP signs **Base USDC**. Solana USDC is accepted by the API; SVM clients can attach `PAYMENT-SIGNATURE` themselves.

## Discovery (x402scan / CDP Bazaar)

Register these public URLs at [x402scan register](https://www.x402scan.com/resources/register):

- `https://api.crewpay.dev/openapi.json`
- `https://api.crewpay.dev/.well-known/x402`

Also:

- `GET https://api.crewpay.dev/api/platforms` → `x402`
- `GET https://api.crewpay.dev/api/agent` → `auth.x402` / `platforms.x402`
- `GET https://api.crewpay.dev/llms.txt`

OpenAPI `info.description` and each paid operation’s `x-payment-info` + `402` response describe the same product. Runtime 402 is authoritative over static metadata.

### Verify the 402 challenge

```bash
curl -i -X POST https://api.crewpay.dev/api/agent/autohire
curl -i -X POST https://api.crewpay.dev/api/agent/launch/unsigned
curl -sS https://api.crewpay.dev/openapi.json | head
curl -sS https://api.crewpay.dev/.well-known/x402
```
